# Paseo Git Manager 开发规划

> 文档日期：2026-11-05  
> 状态：开发规划，尚未实施或完成 Paseo 实机验证。  
> 目标环境：用户从官网下载的公开发行版 Paseo；实施前核对客户端、daemon 和插件 SDK 的准确版本。

## 1. 背景与目标

用户在 Paseo 中进行 vibe coding，希望利用 worktree 隔离任务，但当前使用中遇到以下问题：

- 界面中的提交流程表现为同一 workspace 提交一次后，难以继续提交后续修改。
- 不希望将自动创建的任务分支发布到远端，希望先在本地合并回原分支，再推送原分支。
- 对话归档后仍有任务分支残留，缺少完整的任务收尾流程。
- 自动生成的 worktree 名称难以辨认，无法直观看出任务、分支和目录之间的关系。

插件提供类似 VS Code 源代码管理的界面，围绕以下流程组织功能：

```text
从本地目标分支创建具名任务
            ↓
修改 → 暂存 → 本地提交 → 继续修改（可反复执行）
            ↓
审查全部待合并提交与差异
            ↓
合并回本地目标分支
            ↓
按需推送目标分支
            ↓
归档任务并清理 worktree、任务分支
```

本地合并、远端推送和资源清理分别记录结果。远端暂时不可用时，仍能保留已完成的本地工作；清理失败时可以单独重试。

## 2. 已确认需求与待验证事项

### 2.1 已确认需求

| 编号 | 需求 | 预期行为 |
| --- | --- | --- |
| R1 | 连续提交 | 同一任务分支可多次提交；提交不会自动合并、推送或归档 |
| R2 | 本地任务分支 | 插件不提供默认发布任务分支的流程，不隐式推送任务分支 |
| R3 | 本地合并 | 将任务分支合并到明确选择的本地目标分支 |
| R4 | 推送原分支 | 推送操作展示并使用明确的本地分支、远程和远程目标分支 |
| R5 | 完整收尾 | 提供完成任务后的归档、worktree 清理和本地任务分支清理 |
| R6 | 可读命名 | 任务标题、分支名和目录名可辨认、可自定义 |
| R7 | 可视化管理 | 提供变更列表、diff、暂存、提交和任务状态 |
| R8 | 兼容存量任务 | 发现已有 worktree，支持关联 Paseo workspace 后接管 |

### 2.2 实施前验证

1. 记录用户的 Paseo 客户端、daemon、操作系统和 Git 版本。
2. 复现“一次提交后不能继续”的实际按钮路径、状态变化和报错。Git worktree 本身不存在只能提交一次的限制，目前不能将此现象认定为 Git 限制或已确认的 Paseo 缺陷。
3. 区分用户使用的归档入口究竟归档 agent、workspace，还是同时执行其他动作。
4. 对照发行版对应源码与 SDK 类型，确认插件面板、RPC、订阅和生命周期 hooks 是否可用。
5. 验证归档的清理顺序、脏工作区处理方式、同目录多 workspace 行为，以及是否保留本地分支。
6. 验证任务仍有运行中 agent、终端或服务时，宿主允许怎样停止和归档。

调研期间最新发行入口返回过 v0.15.2，该结果仅是当时的网页观察，不代表用户安装版本，也不直接作为最低兼容版本。最终兼容范围以实机验证为准。

### 2.3 规划默认值

- “原分支”指创建任务时明确记录的本地合并目标，不固定为 `main`。
- 默认普通合并，保留任务中的多次提交；squash 作为后续可选能力。
- 不发布任务分支并不意味着隐藏其中的提交：普通合并后推送目标分支，任务提交也会进入远端历史。
- “本地提交”“合并回目标分支”“推送目标分支”“完成并清理”分开提供。
- 完成流程可以串联操作，但推送必须由用户明确选择；后台刷新与归档通知均不得触发推送。
- 默认在推送成功后清理；也允许明确选择仅本地完成后清理，此时必须确认任务提交已保存在目标分支。
- 单个对话归档不直接等价于整个任务结束。

## 3. 第一版功能范围

### 3.1 任务创建与命名

创建表单包含：仓库、任务标题、本地起始/合并目标分支、任务分支名和目录名。

示例：

```text
任务标题：修复登录重定向
任务分支：task/fix-login
合并目标：develop
目录名称：fix-login
```

名称处理要求：

- 用 Git 校验分支名；目录名遵循所在操作系统的路径约束。
- 对重名提供明确提示或可见的短后缀，不静默恢复成随机名称。
- 标题可以中文，分支和目录提供可编辑的英文建议。
- 优先通过 Paseo 创建并管理 worktree，避免生成宿主不知道的工作目录。
- 第一版对已存在任务支持显示别名，不直接移动运行中的 worktree 或修改其分支名称。

### 3.2 任务总览与接管

按仓库展示任务标题、workspace、worktree 路径、任务分支、目标分支、未提交数量、待合并提交数和当前操作状态。

通过 Git 的实际 worktree 列表和 Paseo workspace 列表进行关联，支持标识：

- 正常关联的任务。
- 多个 workspace 共用的 worktree。
- 仅 Git 中存在、尚未接管的 worktree。
- workspace 已归档但仍待核对的资源。
- worktree 已不存在但任务分支仍存在的残留。

存量任务不能仅凭随机名称或共同祖先猜测原分支。接管时由用户指定目标分支与任务归属。未接管的资源只展示，不自动清理。

### 3.3 更改与连续本地提交

- 分别展示未暂存、已暂存、未跟踪和冲突文件。
- 同一文件可以同时出现在未暂存和已暂存列表。
- 提供整文件暂存、取消暂存、提交说明和提交结果。
- 提交只包含暂存区内容，不默认执行 `commit -a` 或暂存全部文件。
- 成功提交后刷新状态与历史，保留任务和会话，允许立即继续下一次提交。
- 区分工作目录对暂存区的 diff，以及暂存区对 HEAD 的 diff。
- 未跟踪文件、二进制文件、大文件、删除和重命名单独处理。
- 空暂存区、Git 身份未配置、提交 hook 失败和锁冲突均显示真实原因；失败不能清空用户提交说明。

### 3.4 本地合并

合并预览展示任务分支、目标分支、双方当前提交、待合并提交及整体差异。

执行要求：

1. 确定目标分支实际所在 checkout；目标分支被其他 worktree 使用时，不在错误目录强行切换。
2. 检查源与目标是否存在未提交工作、未完成合并或正在写入的任务。
3. 目标没有 checkout 时，明确选择可用目录或受控临时 worktree，不默认改变用户原目录的当前分支。
4. 执行前重新读取源、目标提交；预览已经过期时重新生成预览。
5. 默认正常 merge：可快进则快进，否则生成合并提交；不默认 rebase、squash 或强制重置。
6. 冲突发生后记录所在目录，提供冲突文件列表、继续和中止入口，保留任务资源。
7. 成功后记录源提交和目标结果提交；若源分支后来新增提交，重新标记为待合并。

### 3.5 推送目标分支

- 展示准确的 `本地目标分支 → remote/远程分支` 映射。
- 显式指定推送 refspec，避免依赖全局 `push.default` 或误推当前任务分支。
- 不使用 `--all`、`--mirror` 或默认强制推送。
- 无上游时要求在界面明确选择目标；不自行假定 `origin/main`。
- 使用 daemon 机器已有的 Git 凭据环境，不将凭据传给插件客户端。
- 对非快进、认证失败和网络错误保留本地结果；第一版不自动 pull、rebase 或强推。
- 推送成功状态绑定具体提交，不能将之后的新提交误标为已推送。

### 3.6 归档与清理

提供“完成并清理”流程及可独立重试的清理操作。

清理前确认：

- 当前任务分支 tip 已被目标分支包含，而不是只检查历史上曾经合并过。
- 没有未提交、未跟踪等需要保留的任务文件；忽略文件如 `.env` 也要纳入删除提示和保护策略。
- 没有其他活跃 workspace 或 agent 仍使用该 worktree。
- 资源属于插件创建或用户已明确接管的任务。

执行顺序：

1. 持久化任务与合并证据。
2. 根据宿主支持的生命周期停止相关运行资源并归档相应资源，保留对话记录。
3. 通过 Paseo 的生命周期请求清理其管理的 worktree。
4. 等待并核对 Git worktree 列表和宿主状态，不能把归档回调当作目录删除完成通知。
5. 确认分支未被其他 worktree 检出、tip 未变化且已合并后，再安全删除任务分支。
6. 保存清理结果；部分失败时列出待完成步骤。

默认不强制移除 worktree、不强制删除未合并分支。插件不与宿主同时删除同一目录，不通过手动删除 `.git/worktrees` 元数据清理。

## 4. 界面规划

桌面工作区面板采用三部分布局：

```text
任务：修复登录重定向   task/fix-login → develop
状态：开发中          待合并提交：4

┌──────────────────┬────────────────────────────┐
│ 更改 / 已暂存     │ 当前文件 diff              │
│ 文件列表         │ 未暂存 / 已暂存切换        │
│                  │                            │
├──────────────────┴────────────────────────────┤
│ 提交说明                    [本地提交]         │
│ [查看任务提交] [合并到 develop] [完成并清理]    │
└───────────────────────────────────────────────┘
```

仓库总览中单独提供目标分支推送入口。窄屏使用列表到详情的导航，避免压缩成不可用的多列布局。操作按钮始终展示实际目标分支，不只显示含糊的“同步”。

## 5. 技术架构

```text
Paseo 客户端：React Native 面板
           ↕ 插件 RPC / 订阅
插件服务端：Node.js + TypeScript
           ├─ Paseo SDK：workspace、agent、生命周期
           ├─ Git 适配层：系统 Git 命令、输出解析
           └─ 任务存储：关联关系、操作记录、恢复信息
```

### 5.1 技术选型

| 技术 | 用途 |
| --- | --- |
| TypeScript | 前后端逻辑与共享类型 |
| React / React Native | 宿主内面板、列表与交互 |
| Zod | RPC 输入输出校验 |
| TanStack Query | 请求状态、缓存与失效刷新 |
| Node.js `execFile` / `spawn` | 用参数数组调用系统 Git |
| Paseo Plugin SDK | 面板、命令入口、RPC 和生命周期 |

Git、文件系统和凭据访问仅在 daemon 侧执行。客户端提交 workspace/task 标识，服务端解析已关联的路径；对文件路径、ref 和命令参数分别校验，不提供任意 shell 执行 RPC。

### 5.2 Paseo 接口使用计划

| 接口 | 用途 | 验证重点 |
| --- | --- | --- |
| `addWorkspacePanel()` | 工作区 Git 面板 | 公开发行版的参数与可用位置 |
| `addScreen()`、侧栏入口 | 仓库任务总览 | 多 host 场景的归属 |
| `addCommandCenterItem()` | 打开任务面板 | workspace 上下文 |
| `useWorkspace()` | 读取界面工作区信息 | 缓存与目录变化 |
| `defineRpc()`、`server.handle()`、`useRpc()` | 自定义 Git 操作 | 错误和断线语义 |
| `defineSubscription()`、`useSubscription()` | 状态变化通知 | 版本支持、断线后重新获取快照 |
| `workspaces.create()` | 创建任务 workspace | 起点、分支名与标题 |
| `worktree.create.before` | 具名目录与创建参数 | 字段兼容性、默认请求处理 |
| `workspace.archive()` | 宿主资源归档 | 清理时序与共享使用者 |
| `workspace.archive.after`、`agent.archive.after` | 刷新和协调状态 | 通知不等于清理完成 |

当前调研未确认公开 SDK 提供完整 Git 管理 API 或可复用 diff 编辑器，因此按插件自行实现 Git 适配层和基础 diff 展示估算工作量。hooks 文档标注 `addHook` 从 0.14 起提供，但仍需以目标发行版类型与实测为准。

## 6. 数据与 RPC 设计

### 6.1 任务记录

每个任务至少保存：

- 任务 ID、标题、创建时间和记录版本。
- host 身份、仓库公共 Git 目录、源 checkout。
- 关联 workspace/agent 标识和 worktree 的实际路径。
- 任务分支、本地合并目标、创建时 base commit。
- 明确配置的 push remote 与远程目标 ref。
- 资源归属：插件创建、显式接管或仅发现。
- 最后核实的源提交、合并结果、推送结果和清理进度。

持久化放在 daemon 侧插件私有数据位置，不写入用户仓库的受版本控制文件。具体存储路径遵循目标 SDK 的能力与宿主约定，并采用原子写入、版本迁移和损坏恢复。

不把任务生命周期压缩成一个线性状态：

| 维度 | 示例状态 |
| --- | --- |
| 开发 | 活跃、已归档 |
| 合并 | 未合并、部分已合并、已合并、冲突中 |
| 推送 | 未配置、待推送、已推送、失败 |
| 清理 | 未开始、等待宿主、worktree 已移除、分支已删除、失败 |

这些状态由真实 Git 与宿主状态校验。记录用于关联和恢复，不能替代实际状态。

### 6.2 自定义 RPC

以下均为插件拟定义接口，不是 Paseo 已有 API。

| RPC | 作用 |
| --- | --- |
| `tasks.list` / `tasks.inspect` | 总览和详情 |
| `tasks.create` / `tasks.adopt` | 创建与接管 |
| `git.status` / `git.diff` / `git.log` | 状态、差异和提交历史 |
| `git.stage` / `git.unstage` / `git.commit` | 整文件暂存与本地提交 |
| `tasks.mergePreview` / `tasks.merge` | 预览与执行本地合并 |
| `tasks.mergeContinue` / `tasks.mergeAbort` | 处理未完成合并 |
| `targets.pushPreview` / `targets.push` | 目标分支推送 |
| `tasks.cleanupPreview` / `tasks.complete` | 收尾预览与执行 |
| `tasks.retryCleanup` | 重试清理未完成步骤 |
| `tasks.watch` | 状态变化订阅 |

写操作携带操作 ID；依赖预览的操作还携带预期 ref/OID。服务端保存结果，断线重试时先核对实际状态，避免重复提交、合并或清理。

## 7. 一致性与异常处理

- 普通读操作可以并行；index 写操作按 worktree 串行；merge、分支和清理等共享仓库操作协调到公共仓库级别。
- 插件内队列无法锁住代理或外部终端，因此写入前后都要核实状态，并处理 Git 锁失败，不能自动删锁文件。
- 合并与清理期间避免任务继续写入；具体停止/暂停方式以目标版本支持能力为准，不虚构暂停接口。
- 状态监听需要识别 worktree 自己的 Git 目录和公共 Git 目录，不能假设 `.git` 一定是目录。
- 监听事件进行合并与节流；操作后、页面重新聚焦和断线重连时读取新快照。
- 多客户端共享 watcher；解除订阅或卸载插件时释放监听器和进程。
- 缓存至少区分 host、仓库、worktree 和比较范围。
- 提交、合并、推送、归档和删除不构成跨系统原子事务；每一步持久化进度，提供恢复而不是宣称整体回滚。
- Git 输出设置大小与时间限制；保留退出码和可读错误，不把失败转换成成功状态。

## 8. 开发阶段与交付标准

| 阶段 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| P0 兼容性验证 | 确认版本、复现现有提交行为、验证生命周期 | 兼容矩阵和实机记录；明确可用接口与限制 |
| P1 插件与只读面板 | 脚手架、任务发现、状态、diff | 能安装到目标 Paseo；正确显示真实 worktree 变化 |
| P2 本地提交闭环 | 暂存、取消暂存、提交、刷新 | 同一 workspace 连续完成至少三次提交，期间不推送、不归档 |
| P3 任务创建与命名 | 自定义任务、分支、目录；接管存量任务 | 新任务在 Paseo 正常使用；目标分支明确；重名可处理 |
| P4 本地合并与推送 | 合并预览、冲突处理、目标分支推送 | 本地合并正确；远端只更新选定目标分支 |
| P5 归档与清理 | 生命周期协调、残留扫描、重试 | 已合并任务可完成清理；未合并或仍被使用的资源保留 |
| P6 发布准备 | 跨平台验证、错误体验、说明文档 | 固定兼容范围，给出安装、升级和限制说明 |

P0 中如果目标发行版不支持必要接口，应明确列出缺口，再决定调整实现或提高最低版本；不能仅根据 `main` 分支源码承诺当前发行版可运行。

## 9. 测试与验收

### 9.1 核心验收场景

1. 从本地 `develop` 创建任务 `task/fix-login`，使用可读目录名。
2. 同一 workspace 连续修改并提交三次，任务始终可继续开发。
3. 同一文件同时有已暂存和未暂存修改，提交只包含已暂存部分。
4. 在总览和任务详情看到正确目标分支、待合并提交与差异。
5. 将任务合并到本地 `develop`，任务分支不发布到远端。
6. 推送 `develop`，验证远端更新目标分支且没有新增任务分支引用。
7. 完成任务后保留会话记录，正确归档并移除不再使用的 worktree 和本地任务分支。
8. 任意一步失败，界面如实显示失败步骤；重试不重复创建提交或误删资源。

### 9.2 Git 集成测试

使用临时真实 Git 仓库及本地 bare remote 验证：

- 空仓库/无 HEAD、中文与特殊文件名、删除、重命名、二进制和大文件。
- 多 worktree、多次提交、目标分支在另一个 worktree 被检出。
- 快进、分叉合并、冲突、中止合并和冲突解决后的继续。
- 任务合并后再次新增提交，不得继续沿用“可清理”的旧结论。
- 推送拒绝、远端领先、没有上游与不同 remote 配置。
- 脏 worktree、未跟踪/忽略文件、共享 workspace、任务分支被其他 worktree 使用。
- 宿主清理延迟、操作中断、重复请求和插件重启恢复。
- 失败的 commit hook、index 锁、外部进程改变 refs。

### 9.3 Paseo 实机测试

- 在目标公开版安装、重载和卸载插件。
- 验证用户真实的连续提交路径。
- 验证对话归档与 workspace 归档的实际差异。
- 验证具名 worktree 能被 Paseo 正常发现、运行和清理。
- 验证多会话使用同一 worktree 时的收尾行为。
- 验证断线重连、主题与窄屏布局；支持范围只声明实际测试的平台。

类型检查、模拟测试或 macOS 上的 Git 测试不能作为 Windows、手机端或 Paseo 生命周期已经通过的证据。

## 10. 后续扩展

- 按块/按行暂存。
- 提交图、分支历史比较。
- Squash 合并及其专门的完成证据和清理规则。
- 更完整的冲突编辑器。
- 多仓库批量管理与受控批量清理。
- 远程同步策略、stash、cherry-pick 等高级操作。

第一版不承诺覆盖 Paseo 所有内置 Git 按钮，也不能仅凭插件自身策略阻止代理或外部终端自行推送任务分支。保证范围是插件发起的操作及它明确管理的任务生命周期。
